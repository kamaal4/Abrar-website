## Commands

```bash
npm run dev        # astro dev — http://localhost:4321 (use `astro dev --background`, then astro dev stop/status/logs)
npm run build      # static build into dist/
npm run preview    # serve the built site
npm test           # node:test over src/**/*.test.ts
npm run check      # astro check — TS + template diagnostics
node --test src/utils/emi.test.ts   # a single test file
```

Node ≥ 22.12. Deploys to Cloudflare Workers (Git-connected; builds automatically on push to `main`). Local: `npm run build` → `dist/`, then `wrangler deploy`.

## Architecture

Static Astro + TypeScript + Tailwind v4. No backend, no CMS, no runtime data — it builds to plain HTML.

- **Data is code.** All inventory lives in typed arrays in `src/data/` (`properties.ts`, `projects.ts`, `locations.ts`, `images.ts`). Pages never touch the arrays — they call accessor functions (`getAllProperties()`, `getPropertyBySlug()`, …). Those accessors are the seam where a real backend would land. An image reference that doesn't resolve to a file in `src/assets/` fails `npm run build`. `location` is a plain string, though: a typo builds fine and shows up as a raw slug label. `src/data/data.test.ts` is the only thing that catches it, so run `npm test` after editing data.
- **`src/config/site.ts` is the single source of truth** for brand, contact, social and navigation; the contact details, social links and disclosure come from `src/config/settings.json`, which Abrar edits through `/admin`. Empty values are handled gracefully (no email → `/contact` says so; no phone → Call buttons disappear).
- **Every WhatsApp link** comes from `getWhatsAppLink()` in `src/utils/whatsapp.ts` — the conversion goal is a WhatsApp enquiry. Never hardcode a `wa.me` URL.
- **Every internal link** goes through `url()` in `src/utils/url.ts`, which applies the base path. `SITE_URL` and `BASE_PATH` env vars (read in `astro.config.mjs`) are the only deployment config — a project Pages URL and a custom domain both work unchanged.
- **Images** are referenced via `<Img image=… alt=… />` by a bare key (`aasheen-1` → `src/assets/aasheen-1.webp`) or the path the editor stores (`/src/assets/foo.webp`). The original images are registered in `src/data/images.ts` with alt + credit; that registry alt wins, and the `alt` prop is the fallback for editor uploads, so always pass the listing's title. Anything with an `author` auto-lists on `/credits`.
- **`/admin`** is Sveltia CMS (`public/admin/config.yml`, pinned version in `public/admin/index.html`). Each save commits to `main`, which Cloudflare rebuilds. Its GitHub login is the only Worker code (`worker/sveltia-cms-auth.js`, vendored; `wrangler.jsonc` routes just `/oauth/*` to it).
- **Blog** is a content collection: `src/content/blog/*.md`, frontmatter validated by `src/content.config.ts`.
- **SEO/JSON-LD** is centralised in `src/layouts/BaseLayout.astro`; pages contribute page-specific structured data via the `jsonLd` prop. `robots.txt` is generated by `src/pages/robots.txt.ts`.

Only three things use client-side JS (`src/scripts/`): property filters (all cards are in the HTML; filtering hides them and syncs to the URL — works with JS off), the scripted assistant state machine, and favourites (`localStorage` in try/catch). The EMI calculator (`src/utils/emi.ts`) is a pure, unit-tested function rendered server-side first.

## Design

`DESIGN.md` documents the intent behind the tokens in the `@theme` block of `src/styles/global.css`; `PRODUCT.md` holds the audience and positioning. Read both before changing colour, type or copy — they encode decisions (the dark "Instrument" ground, the single azure `beam` accent, no invented ratings or review counts) that are easy to undo by accident. Three rules the comment at the top of `global.css` spells out: the ground is cool (hue 260, never warm) and never pure black; elevation is light (a 1px top highlight), not shadow; anything sitting on `beam` takes `--color-on-beam`, never white.

Colours are OKLCH and measured to WCAG AA, ratios recorded in `DESIGN.md` — there's no audit script, so if you change a lightness, re-measure it by hand and update the table.

`@layer components` in `global.css` is a real class vocabulary — `.shell`, `.band`, `.card`, `.btn-*`, `.mono-label`, `.glass`, `.link-wipe`. Reuse it; a new one-off component style is nearly always a duplicate of something already there.
